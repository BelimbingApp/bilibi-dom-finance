# Opening invoices

Read finance.receivables.opening.context for the current company's approved conversion entry, book precision, exact CSV header, retained batch and imported item identifiers. Prepare setup and mapping in separate reviewed writes; plans preview dependent steps before executing earlier steps.

Use finance.receivables.opening.import with company_id, source_reference, currency_code and csv plus an active invoice series_id. Every current or former control with a non-zero approved opening balance is included automatically. Add only old-system controls that were never configured here to historical_control_account_codes. Preview the complete register and inspect each source ID, date, amount and account mapping, then commit the exact reviewed input once. Every automatic or added control must reconcile exactly, including a control with no CSV rows. Import creates no ledger entry or source-period tax lines. The reviewer must be independent of the opening journal's source preparer. An override_reason invokes the existing duty-separation controls and records an exception; it is not a bypass.

A direct import accepts 500 rows and 128 KiB. For a larger register, call `finance.receivables.opening.stage` for each numbered batch. Supply `part`, `part_count`, the same source reference and historical_control_account_codes, and a CSV containing the header and up to 500 rows. Commit each reviewed batch. Identical retries return the retained batch; changed bytes, control mapping or instructions require a new source reference. Staging creates no settleable records.

Read `opening.context` to resume missing batches; it lists batch metadata without source CSV, and pages imported items with `limit` (default 200, at most 500) and `items_after` (pass the previous `items_next`; `item_count` is the total). Once all batches are committed, call `opening.import` with `staged: true`, the retained source reference and `csv: ""`. Preview every source row and the whole-register reconciliation, then commit once. The final reviewer must be independent of the opening preparer and every batch preparer. Limits: 200 batches, 10,000 rows and 32 MiB of assembled CSV.

To correct a reconciled register, stage a new export with a new source reference. Name the current `replaces_batch_id`, and a `reason` on every batch. A correction takes effect at the conversion date; there is no later effective date. Keep every previously recognized account and its opening balance. Reverse dependent receipts and approved write-offs through their owners first. Reject pending write-offs. An issued credit note still blocks replacement; it cannot be discarded as source evidence.

Preview returns `state: "previewed"`. A retained source batch returns `state: "committed"`. Final approval creates a `reconciled` decision and all records atomically. A refusal leaves the current register intact. Every export, prior snapshot, approval and replacement link remains evidence. Reports at or after the conversion date show the current register. Reproduce older reports with every returned pin, including the opening-batch pin. Never combine a newer register pin with an older posting pin to claim an earlier reconciliation.

Import positive residuals, retaining original gross totals, document/due dates and source references. Receivables resolves customer_code and Payables resolves vendor_code as the Core party code. Include party_kind (company or person) to identify the Core kind. Receivables requires an active Finance customer; vendor_name remains source evidence. Map each row to its original control account; each mapped account must reconcile separately. Opening credits and currency translation are not yet supported. Settle through the normal reviewed receipt/payment operations after conversion. Aging excludes these records before conversion. Source-period tax and prior allocations remain external evidence.
