# Opening bills

Read finance.payables.opening.context for the current company's approved conversion entry, book precision, exact CSV header, retained batch and imported item identifiers. Prepare setup and mapping in separate reviewed writes; plans preview dependent steps before executing earlier steps.

Use finance.payables.opening.import with company_id, source_reference, currency_code and csv. Preview the complete register and inspect each source ID, date, amount and account mapping, then commit the exact reviewed input once. The register must reconcile exactly to the approved opening accounts. Import creates no ledger entry or source-period tax lines. The reviewer must be independent of the opening journal's source preparer. An override_reason invokes the existing duty-separation controls and records an exception; it is not a bypass.

A direct import accepts 500 rows and 128 KiB. For a larger register, call `finance.payables.opening.stage` for each numbered batch. Supply `part`, `part_count`, the same source reference and mapping, and a CSV containing the header and up to 500 rows. Commit each reviewed batch. Identical retries return the retained batch; changed bytes or instructions require a new source reference. Staging creates no settleable records.

Read `opening.context` to resume missing batches. Once all batches are committed, call `opening.import` with `staged: true`, the retained source reference and `csv: ""`. Preview every source row and the whole-register reconciliation, then commit once. The final reviewer must be independent of the opening preparer and every batch preparer. Limits: 200 batches, 100,000 rows and 32 MiB of assembled CSV.

To correct a reconciled register, stage a new export with a new source reference. Name the current `replaces_batch_id`, a `reason` and an `effective_date` on every batch. Keep every previously recognized account and its opening balance. The correction date cannot precede conversion, the prior correction or a dependent reversal. Reverse dependent receipts, supplier payments, approved write-offs, depreciation and disposals through their owners first. Reject pending payment requests and write-offs, and void unposted supplier notes. An issued credit note or posted supplier note still blocks replacement; it cannot be discarded as source evidence.

Preview returns `state: "previewed"`. A retained source batch returns `state: "committed"`. Final approval creates a `reconciled` decision and all records atomically. A refusal leaves the current register intact. Every export, prior snapshot, approval and replacement link remains evidence. Reports before the correction date retain the prior register. Reproduce older reports with every returned pin, including the opening-batch pin for invoices/bills and the asset-number pin for assets. Never combine a newer register pin with an older posting pin to claim an earlier reconciliation.

Asset corrections retain source cost and accumulation and replace prospective assumptions. Reverse a standing disposal before its depreciation runs, newest run first. Reversed months remain consumed; the next unconsumed month catches up the corrected prospective schedule. The opening journal remains protected against reversal, including after correction. Changing its recognized balances is refused; never repair import state with ordinary invoices, bills, acquisitions or repeated postings.

Import positive residuals, retaining original gross totals, document/due dates and source references. Receivables links customer_code to an active customer; Payables resolves vendor_code to an active Finance vendor linked to an active Core company, keeping vendor_name as source evidence. Opening credits, multiple historical controls and currency translation are not yet supported. Settle through the normal reviewed receipt/payment operations after conversion. Aging excludes these records before conversion. Source-period tax and prior allocations remain external evidence.
