# Opening asset register

Read finance.fixed_assets.opening.context for the current company's approved conversion entry, book precision, exact CSV header, retained batch and imported item identifiers. Prepare setup and mapping in separate reviewed writes; plans preview dependent steps before executing earlier steps.

Use finance.fixed_assets.opening.import with company_id, source_reference, currency_code and csv. Preview the complete register and inspect each source ID, date, amount and account mapping, then commit the exact reviewed input once. The register must reconcile exactly to the approved opening accounts. Import creates no ledger entry or source-period tax lines. The reviewer must be independent of the opening journal's source preparer. An override_reason invokes the existing duty-separation controls and records an exception; it is not a bypass.

A direct import accepts 500 rows and 128 KiB. For a larger register, call `finance.fixed_assets.opening.stage` for each numbered batch. Supply `part`, `part_count`, the same source reference and mapping, and a CSV containing the header and up to 500 rows. Commit each reviewed batch. Identical retries return the retained batch; changed bytes or instructions require a new source reference. Staging creates no settleable records.

Read `opening.context` to resume missing batches; it lists batch metadata without source CSV, and pages imported items with `limit` (default 200, at most 500) and `items_after` (pass the previous `items_next`; `item_count` is the total). Once all batches are committed, call `opening.import` with `staged: true`, the retained source reference and `csv: ""`. Preview every source row and the whole-register reconciliation, then commit once. The final reviewer must be independent of the opening preparer and every batch preparer. Limits: 200 batches, 10,000 rows and 32 MiB of assembled CSV.

To correct a reconciled register, stage a new export with a new source reference. Name the current `replaces_batch_id`, and a `reason` on every batch. A correction takes effect at the conversion date; there is no later effective date. Keep every previously recognized account and its opening balance. Reverse dependent depreciation and disposals through their owner first.

Preview returns `state: "previewed"`. A retained source batch returns `state: "committed"`. Final approval creates a `reconciled` decision and all records atomically. A refusal leaves the current register intact. Every export, prior snapshot, approval and replacement link remains evidence. Reports at or after the conversion date show the current register. Reproduce older reports with every returned pin, including the asset-number pin. Never combine a newer register pin with an older posting pin to claim an earlier reconciliation.

Asset corrections retain source cost and accumulation and replace prospective assumptions. Reverse a standing disposal before its depreciation runs, newest run first. Reversed months remain consumed; the next unconsumed month catches up the corrected prospective schedule. The opening journal remains protected against reversal, including after correction. Changing its recognized balances is refused; never repair import state with ordinary invoices, bills, acquisitions or repeated postings.

Follow the [opening-register conversion rules](README.md#opening-asset-register-at-conversion) for source balances, remaining life and the full first-month convention. For depreciation runs, disposal and the other asset operations, use the [lifecycle guide](lifecycle-guide.md).

Optional `source_evidence` is an object keyed by source asset ID, containing `history`, `source_period_expense` and `tax_capital_allowances` arrays. The README gives the exact shapes and limits. Supply each staged batch's evidence with that batch; leave it empty for final staged reconciliation. The review, retained asset and auditor evidence share these facts. They never change the CSV's prospective estimates or post historical expenses, impairments, disposals or tax allowances. A retry must retain the same evidence as well as the same CSV and correction instructions.

The review's `class_totals` groups cost and accumulation by category and account pair. The `reconciliation` combines shared accounts and ties them to the approved opening trial balance. Read `month_convention` before approval: source balances precede conversion, and the first full prospective month is recognized at that calendar month's end, including a mid-month cut-off.
